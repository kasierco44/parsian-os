# سیاست امنیت و حفاظت داده

## الزامات پایه
- اصل حداقل دسترسی برای کاربران، سرویس‌ها و توکن‌ها.
- کنترل مجوز در سمت سرور برای هر درخواست و هر منبع؛ مخفی‌کردن دکمه در UI کنترل امنیتی نیست.
- TLS برای تمام ارتباطات بیرونی و داخلی حساس.
- ذخیره رمز عبور با الگوریتم استاندارد مقاوم مانند Argon2id یا گزینه امن پشتیبانی‌شده؛ هرگز رمز خام ذخیره نشود.
- MFA برای مدیران و دسترسی‌های حساس، در صورت پشتیبانی عملیاتی.
- محدودسازی نرخ، قفل/تأخیر تدریجی ورود و ثبت رخدادهای امنیتی.
- اعتبارسنجی ورودی، جلوگیری از SQL injection، XSS، CSRF و کنترل آپلود فایل.
- اسرار، کلید API، رمز دیتابیس، توکن و فایل `.env` هرگز commit نشوند.

## داده‌های حساس
اطلاعات مشتری، شماره تماس، مانده مالی، تصاویر اسناد، چک‌ها و اطلاعات کارکنان باید طبقه‌بندی و فقط در حد نیاز نقش‌ها نمایش داده شوند. داده تست باید ساختگی یا ناشناس‌سازی‌شده باشد.

## ثبت رویداد (Audit)
موارد زیر ثبت شوند: ورود ناموفق/موفق، تغییر نقش و مجوز، ایجاد/ویرایش/ابطال سند مالی، تغییر موجودی، تأییدها، خروجی‌گرفتن از داده و تغییر تنظیمات. رویدادها شامل عامل، زمان، هدف، نوع عملیات و شناسه همبستگی باشند؛ از ثبت رمز و اسرار خودداری شود.

## پشتیبان‌گیری و بازیابی
- پشتیبان رمزگذاری‌شده و دسترسی محدود.
- نگهداری نسخه‌های جدا از سرور اصلی.
- تعریف RPO/RTO پس از شناخت نیاز کسب‌وکار.
- آزمون دوره‌ای بازیابی؛ وجود فایل backup به‌تنهایی اثبات قابلیت بازیابی نیست.

## انتشار امن
- بازبینی کد و وابستگی‌ها.
- تست خودکار و بررسی آسیب‌پذیری.
- جداسازی dev/test/staging/production.
- حساب سرویس با حداقل مجوز.
- برنامه rollback و پشتیبان قبل از migrationهای مخرب.

## گزارش رخداد
هر رخداد مشکوک باید ثبت، سطح‌بندی، مهار و بررسی شود. شواهد حفظ شوند و چرخش کلیدها/توکن‌های در معرض خطر در اولویت قرار گیرد.
