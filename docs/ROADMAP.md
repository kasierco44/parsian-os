# نقشه راه اجرایی PARSIAN OS

این نقشه راه ترتیب وابستگی‌ها را مشخص می‌کند. تکمیل هر مرحله فقط پس از تحویل قابل مشاهده، تست و تأیید معیارهای پذیرش اعلام می‌شود.

| مرحله | خروجی | معیار عبور |
|---|---|---|
| 1. مخزن و محیط | مخزن خصوصی، شاخه‌ها، قواعد همکاری | دسترسی و شاخه main بررسی شده |
| 2. معماری | اسناد معماری، دامنه‌ها و ADRها | تأیید مرز ماژول‌ها و پشته فنی |
| 3. پایه داده | PostgreSQL، migration و مدل پایه | migration از صفر و rollback تست شود |
| 4. هویت و امنیت | کاربران، نقش‌ها، مجوزها، نشست‌ها، audit | تست دسترسی مجاز/غیرمجاز موفق |
| 5. Backend پایه | API نسخه‌بندی‌شده، خطاها، logging | تست API و مستندات OpenAPI |
| 6. رابط مرکزی | داشبورد، ناوبری فارسی RTL، تنظیمات | تست پذیرش مدیر و کاربران |
| 7. CRM و فروش | مشتری، سرنخ، پیگیری، پیش‌فاکتور و سفارش | چرخه فروش انتها به انتها تست شود |
| 8. مالی | دریافت، پرداخت، چک، مانده و گزارش | تطبیق جمع‌ها و audit مالی |
| 9. انبار و تولید | کالا، بچ، گردش موجودی، مواد و تولید | آزمون موجودی و رهگیری گردش |
| 10. فروش دورکار | اپ/کلاینت ویزیتور، تخصیص، تماس و وصول | همگام‌سازی و محاسبه پورسانت تست شود |
| 11. AI و اتوماسیون | n8n، دستیار و هشدارها | مجوز، ثبت رویداد و تأیید انسانی |
| 12. انتشار | CI، staging، امنیت، backup/restore | آزمون بازیابی و تأیید Go-Live |

## ترتیب اجرایی نزدیک
1. بازبینی این اسناد و ثبت تصمیم‌های معماری.
2. بررسی ساختار و فناوری پروژه‌های فعلی؛ بدون تغییر یا حذف آن‌ها.
3. ایجاد اسکلت Backend و تست‌های پایه در شاخه مستقل.
4. ساخت schema اولیه و migrationها.

## قواعد تحویل
- هر مرحله باید شامل تغییرات واقعی، فهرست فایل‌ها، روش اجرا، تست‌های اجراشده و محدودیت‌های باقی‌مانده باشد.
- تست اجرا نشده نباید «موفق» گزارش شود.
- تغییرات تولیدی ابتدا در staging و با پشتیبان قابل بازگشت انجام می‌شوند.
- داده واقعی مشتری یا اطلاعات بانکی در محیط توسعه استفاده نمی‌شود.
