# نقشه راه اجرایی PARSIAN OS

این نقشه راه برای معماری تأییدشده «افزونه مرکزی WordPress + چهار کلاینت مستقل + همگام‌سازی آفلاین» تنظیم شده است. تکمیل هر مرحله فقط پس از تحویل قابل مشاهده، تست و معیار پذیرش اعلام می‌شود.

| مرحله | خروجی | معیار عبور |
|---|---|---|
| 1. تثبیت معماری | افزونه WordPress به‌عنوان مرجع داده؛ چهار محصول مستقل؛ Web و Windows برای حسابداری/مدیریت | ADR ثبت و قراردادها بازبینی شوند |
| 2. ممیزی دارایی‌ها | بررسی کد واقعی افزونه نصب‌شده، مخزن Android و محیط WordPress | فهرست نسخه‌ها، وابستگی‌ها و ریسک‌ها؛ بدون بازنویسی حدسی |
| 3. هسته افزونه | ماژول‌ها، جداول اختصاصی، migration و تنظیمات | نصب/ارتقا/rollback روی staging موفق |
| 4. هویت و API | ورود یکپارچه، نقش/مجوز، device registry و REST API v1 | تست مجاز/غیرمجاز و ابطال نشست موفق |
| 5. قرارداد همگام‌سازی | outbox/inbox، delta cursor، idempotency، versioning و تعارض | قطع شبکه، retry و عدم ثبت تکراری تست شود |
| 6. وب‌اپ‌ها | پنل حسابداری و مدیریت RTL به‌صورت وب/PWA | نصب PWA، نقش‌ها و offline shell تست شوند |
| 7. Windows Accounting | برنامه مستقل Windows، SQLite و Sync | نصب پاک، اجرای آفلاین و همگام‌سازی تست شود |
| 8. Windows Management | برنامه مستقل Windows، SQLite و Sync | نقش مدیر، تأییدها و قطع/وصل شبکه تست شود |
| 9. Android Customer | اپ مستقل مشتری با cache و صف عملیات مجاز | سفارش پیش‌نویس آفلاین و sync تست شود |
| 10. Android Seller | اپ مستقل فروشنده با CRM و گردش فروش | مشتری/پیگیری/پیش‌فاکتور آفلاین و sync تست شود |
| 11. اتصال دامنه‌ها | فروش، مالی، انبار، پورسانت، اعلان و گزارش | تست انتهابه‌انتها و تطبیق داده انجام شود |
| 12. انتشار | امضا، نسخه‌بندی، پایش، backup/restore و راهنمای نصب | آزمون بازیابی و تأیید Go-Live |

## قواعد تحویل
- هر مرحله باید تغییرات واقعی، فایل‌های تغییرکرده، روش اجرا، تست‌های اجراشده و محدودیت‌های باقی‌مانده را گزارش کند.
- تست اجرا نشده نباید «موفق» گزارش شود.
- کد موجود بدون دریافت/بررسی منبع واقعی بازنویسی نمی‌شود.
- تغییرات ابتدا در شاخه کاری و staging؛ production فقط با پشتیبان قابل بازگشت.
- اطلاعات واقعی مشتری، چک و حساب بانکی در تست استفاده نمی‌شود.
