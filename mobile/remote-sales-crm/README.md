# پارسیان‌یار ویزیتور — نسخه آزمایشی اندروید

این پروژه یک پوسته آزمایشی Expo / React Native برای بررسی محیط کار ویزیتورهای دورکار است.

## اجرا روی گوشی با Expo Go
1. Node.js و npm را روی رایانه نصب کنید.
2. در این پوشه اجرا کنید: `npm install`
3. سپس: `npx expo start`
4. QR را با Expo Go اسکن کنید.

## ساخت APK آزمایشی
Workflow گیت‌هاب در مسیر `.github/workflows/remote-sales-crm-android.yml` با هر push به شاخه این اپ، APK نوع Debug می‌سازد و به‌عنوان Artifact منتشر می‌کند.

## محدودیت‌های این نسخه
- ورود، مشتریان، سفارش‌ها، اهداف و پورسانت داده نمونه هستند.
- هیچ API، دیتابیس یا حساب کاربری واقعی متصل نیست.
- برای انتشار عملیاتی باید احراز هویت، API سرور و سیاست دسترسی ویزیتور به PARSIAN OS متصل شوند.

## اتصال API — زیرساخت مرحله بعد

یک لایه API در `src/api/client.js` اضافه شده است که با قرارداد فعلی Backend کار می‌کند:
- `POST /api/v1/auth/login` برای دریافت توکن
- `GET /api/v1/auth/me` برای دریافت هویت حساب واردشده
- `GET /api/v1/customers` برای فهرست و جست‌وجوی مشتریان (با اعمال دسترسی سمت سرور)

توکن دسترسی با `expo-secure-store` در فضای امن برنامه نگهداری می‌شود. هیچ نشانی سرور یا رمز عبوری داخل مخزن ثبت نمی‌شود.

برای فعال‌سازی اتصال در محیط build، متغیر محیطی `EXPO_PUBLIC_API_BASE_URL` باید به نشانی کامل API شامل پیشوند نسخه، مانند `https://api.example.com/api/v1`، تنظیم شود. مقدار نمونه بالا صرفاً قالب است و نشانی واقعی سرور محسوب نمی‌شود.

**وضعیت فعلی:** لایه ارتباط و ذخیره امن توکن آماده شده، اما رابط کاربری هنوز به آن متصل نشده است. اتصال عملیاتی پس از ادغام و استقرار امن ماژول‌های احراز هویت، RBAC و مشتریان انجام می‌شود. تا آن زمان نسخه APK نمایشی باقی می‌ماند.

### ورود و تغییر رمز اولیه
- فرم ورود با نام کاربری و رمز عبور سازمانی به API متصل است.
- اگر Backend پاسخ دهد که تغییر رمز اجباری است، برنامه فرم تغییر رمز را نمایش می‌دهد و تا تغییر موفق رمز اجازه ورود به CRM نمی‌دهد.
- رمز جدید باید حداقل ۱۲ نویسه باشد؛ اعتبارسنجی نهایی همچنان در Backend انجام می‌شود.
- نشست‌های معتبر در SecureStore نگهداری می‌شوند.

### تنظیم نشانی API برای ساخت APK
در GitHub Repository Settings → Secrets and variables → Actions → Variables یک متغیر با نام `PARSIAN_API_BASE_URL` بسازید و مقدار آن را نشانی HTTPS واقعی API به‌همراه پیشوند نسخه قرار دهید؛ برای مثال قالب `https://<your-domain>/api/v1` (این آدرس نمونه است، نه سرور مستقر). Workflow مقدار را در زمان build به `EXPO_PUBLIC_API_BASE_URL` منتقل می‌کند. تا قبل از ثبت نشانی واقعی، برنامه به‌صورت آفلاین/نمایشی اجرا می‌شود و ورود واقعی فعال نیست.
